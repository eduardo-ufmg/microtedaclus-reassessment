\section{Base Improvement}
\label{sec:base_improvement}

While the iterative corrections evaluated in \cref{chap:ModelCorrection} successfully restored theoretical consistency and rectified fundamental algorithmic flaws, the resulting implementation, \modelname{macrocluster-activation}, inherited severe software engineering bottlenecks from the legacy codebase. Because this chapter explores substantive methodological proposals and algorithmic refinements, establishing a computationally efficient, structurally clean reference implementation is essential. To this end, prior to introducing novel algorithmic modifications, we formulate \modelname{base-improved} as a strict non-functional refactoring designed to eliminate computational bottlenecks and memory overhead while preserving the exact mathematical clustering behavior of \modelname{macrocluster-activation}.

\subsection{Architectural Deficiencies of the Legacy Implementation}

Comprehensive profiling of the legacy implementation revealed four primary micro-architectural deficiencies that severely constrained throughput and scalability:

\begin{enumerate}
    \item \textbf{Unstructured Heap Memory and Dynamic Table Overhead}: Microclusters were instantiated as unconstrained Python dictionaries. As \cref{tab:profiling_micro_benchmarks} demonstrates, each dictionary incurs nearly $0.5$\,KB heap memory overhead attributable to dynamic hash-table bucketing, pointer indirection, and string key storage. For bivariate data, this represents approximately half the total microcluster heap footprint. In long-running streams with numerous active microclusters, this unconstrained allocation introduces significant memory fragmentation and garbage collection overhead.

    \item \textbf{Quadratic Macrocluster Graph Resolution}: Resolving the constituent microclusters of a macrocluster relied on iterative linear scans over the entire population via generator expressions \codename{next(m for m in self.micro\_clusters if m["id"] == id)}. For a stream state with $K$ microclusters partitioned into $|\mathcal{M}|$ macroclusters, this yielded $\mathcal{O}(|\mathcal{M}_j| \cdot K)$ scanning cost per lookup during both maintenance and inference phases.

    \item \textbf{Call Boundary and Argument Boxing Overhead in Numba Wrappers}: Low-level arithmetic operations, such as pairwise Euclidean distance calculations, were delegated to isolated JIT-compiled Numba routines decorated with \codename{@jit(nopython=True)}. However, because these routines were invoked at a scalar granularity within nested Python loops, the overhead of Python C-API argument boxing, tuple packing/unpacking, and call boundary dispatch dominated execution time. As measured in \cref{tab:profiling_micro_benchmarks}, evaluating pairwise distance through the scalar Numba wrapper is slower than inlined native NumPy and orders of magnitude slower than vectorized BLAS-level evaluation.

    \item \textbf{Unvectorized Batch Prediction Call Volume}: During evaluation, classification of incoming query batches $X \in \mathbb{R}^{N \times D}$ was computed sample-by-sample. For every query point, the algorithm repeatedly recomputed macrocluster density means, filtered active units via list comprehensions, and evaluated scalar typicalities. Profiling a standard batch of $N = 100$ samples across $K = 101$ microclusters in \cref{tab:profiling_micro_benchmarks} revealed that this nested design triggered many linear generator searches and dynamic membership invocations, consuming milliseconds per batch.
\end{enumerate}

\subsection{Optimized Architecture}

To resolve these bottlenecks, \modelname{base-improved} introduces a modernized architecture structured around four non-functional optimizations:

\begin{itemize}
    \item \textbf{Slotted Dataclasses}: Microclusters are redefined using slotted dataclasses (\codename{@dataclass(slots=True)}). By eliminating dynamic hash tables and storing attributes in flat, fixed-offset C-level pointer arrays, per-microcluster memory overhead is reduced by across all dimensions, saving half of the heap memory at $D=2$ anda third at $D=64$, shows \cref{tab:profiling_micro_benchmarks}, Panel A.

    \item \textbf{Constant-Time Primary Key Indexing}: An internal lookup map \codename{dict[int, MicroCluster]} maintains direct pointer references to active units by integer ID. Resolving macrocluster components is thereby reduced from a quadratic generator scan to direct $\mathcal{O}(|\mathcal{M}_j|)$ dictionary lookups, completely eliminating the legacy \codename{next(...)} generator calls.

    \item \textbf{Vectorized Graph Maintenance}: Macrocluster intersection detection is streamlined using optimized distance matrices via \codename{scipy.spatial.distance.cdist} and broadcasted deviation arrays $2(\sqrt{\sigma_i^2} + \sqrt{\sigma_j^2})$. As documented in Panel B of \cref{tab:profiling_micro_benchmarks}, amortized pairwise distance evaluation latency achieves a significant speedup and entirely eliminates scalar JIT wrapper calls.

    \item \textbf{Fully Vectorized Batch Inference}: Batch prediction is refactored into matrix operations. For each macrocluster, active cluster centroids $\mu$, variances $\sigma^2$, sample counts $S$, and relative weights are stacked into contiguous NumPy arrays once per batch. Pairwise squared Euclidean distances for all $N$ samples are computed simultaneously via tensor broadcasting $\|X - \mu\|^2$, followed by vectorized typicality evaluation and matrix-vector projection. As shown in Panel C, total function calls drops drastically, reducing batch latency and achieving an prediction speedup of over $200\times$.
\end{itemize}

The statistical evaluations reported in \cref{tab:base_imp_ari_overall,tab:base_imp_ari_fifth,tab:base_imp_ari_steadystate,tab:base_imp_ari_diff} empirically confirm the strict mathematical invariance of the refactoring. While clustering behavior remains identical, the macroscopic computational gains are profound:
\begin{itemize}
    \item \textbf{Inference Throughput}: As shown in \cref{tab:base_imp_time_predict_cum_ms}, cumulative prediction times collapsed across all benchmarks, placing \modelname{base-improved} in the top statistical tier across $100\%$ of datasets and reducing total inference runtime by multiple orders of magnitude.
    \item \textbf{Training Efficiency}: Fitting times (\cref{tab:base_imp_time_fit_cum_ms}) decreased significantly, particularly on dense synthetic streams where frequent topological graph updates previously suffered from Numba wrapper dispatch overhead.
    \item \textbf{Memory Footprint}: As documented in \cref{tab:base_imp_memory_max_bytes,tab:base_imp_memory_steadystate_bytes}, memory consumption dropped substantially, especially in higher-dimensional configurations such as \datasetname{SCL-32} and \datasetname{SCL-64}, where maximum memory dropped by over $88\%$ (from $1.25$\,MB to $133$\,KB and $2.34$\,MB to $96$\,KB, respectively).
\end{itemize}

By eliminating software bottlenecks, achieving orders-of-magnitude faster inference, and slashing memory consumption without altering clustering outputs, \modelname{base-improved} establishes a clean, high-performance foundation. All subsequent algorithmic proposals in this chapter are evaluated directly against this modernized base, ensuring that observed variations stem strictly from methodological modifications rather than implementation artifacts.

\section{Reparameterization of the \texorpdfstring{$m$}{m} Function}
\label{sec:reparameterization_of_m_function}

The function may be generalized as

\begin{equation} \label{eq:generalized_m}
    m(k) = \frac{\text{up}}{1 + e^{-a(k-b)}}, \text{up} > 1
\end{equation}

\MicroTEDAClus sets

\begin{align}
    \text{up} &= 3 \\
    a &= 0.007 \\
    b &= 100
\end{align}

so

\begin{align}
    m(2) &\approx 1.005 \\
    m(1000) &\approx 2.995
\end{align}

which approximately meets the function definition criteria in \cite{maia2020evolvclus}. If those criteria are substituted by

\begin{align}
    m(3) &= 1 \\
    \lim_{k \to \infty} m(k) &= \text{up}
\end{align}

then

\begin{align}
    \lim_{k \to \infty} \frac{\text{up}}{1 + e^{-a(k-b)}} &= \text{up} \\
    \lim_{k \to \infty} e^{-a(k-b)} &= 0 \\
    \implies a &> 0
\end{align}

and

\begin{align}
    \frac{\text{up}}{1 + e^{-a(3-b)}} &= 1 \\
    e^{-a(3-b)} &= \text{up} - 1 \\
    -a(3-b) &= \ln(\text{up} - 1) \\
    b &= 3 + \frac{\ln(\text{up} - 1)}{a} \label{eq:b_of_a}
\end{align}

which reduces the tunable parameters in \cref{eq:generalized_m} from $(a, b, \text{up})$ to $(a, \text{up})$. It is worth noting that because $k \in \mathbb{N}$ and \cref{subsubsec:incorrect_condition_logic} shows that $m(2)$ does not matter for \cref{eq:corrected_condition_logic_for_outliers}, $k = 3$ is the actual lower bound the function's domain. From \cref{eq:b_of_a} and \cref{eq:generalized_m},

\begin{align}
    m(k) &= \frac{\text{up}}{1 + e^{-a(k-(3 + \frac{\ln(\text{up} - 1)}{a}))}} \\
    m(k) &= \frac{\text{up}}{1 + e^{-a(k-3) + \ln(\text{up} - 1)}} \\
    m(k) &= \frac{\text{up}}{1 + e^{-a(k-3)}e^{\ln(\text{up} - 1)}} \\
    m(k) &= \frac{\text{up}}{1 + (\text{up} - 1)e^{-a(k-3)}}
\end{align}

If $k_{95\%} = m^{-1}(0.95\text{up})$,

\begin{align}
    0.95\text{up} &= \frac{\text{up}}{1+(\text{up}-1)e^{-a(k_{95\%}-3)}} \\
    1 + (\text{up}-1)e^{-a(k_{95\%}-3)} &= \frac{\text{up}}{0.95\text{up}} = \frac{1}{0.95} = \frac{20}{19} \\
    (\text{up}-1)e^{-a(k_{95\%}-3)} &= \frac{20}{19} - 1 = \frac{1}{19} \\
    e^{-a(k_{95\%}-3)} &= \frac{1}{19(\text{up}-1)} \\
    -a(k_{95\%}-3) &= \ln\left(\frac{1}{19(\text{up}-1)}\right) \\
    a &= -\frac{1}{k_{95\%}-3}\ln\left(\frac{1}{19(\text{up}-1)}\right) \\
    a &= \frac{1}{k_{95\%}-3}\ln(19(\text{up}-1))
\end{align}

Then,

\begin{align}
    m(k) &= \frac{\text{up}}{1 + (\text{up} - 1)e^{-\frac{1}{k_{95\%}-3}\ln(19(\text{up}-1))(k-3)}} \\
    m(k) &= \frac{\text{up}}{1 + (\text{up} - 1)(19(\text{up}-1))^{-\frac{k-3}{k_{95\%}-3}}}
\end{align}

Which have two tunable parameters, $\text{up}$ and $k_{95\%}$, instead of the three parameters of \cref{eq:generalized_m}. Furthermore, those parameters directly interpretable under \cref{eq:outlier_condition}:

\begin{itemize}
    \item $\text{up}$ is the steady-state boundary for a mature microcluster. It defines the maximum $m\sigma$ limit used to classify outliers once the cluster has observed a highly representative sample size.
    \item $k_{95\%}$ is the sample size at which the microcluster is considered stable. A lower $k_{95\%}$ causes the cluster to rapidly trust its estimated parameters, while a higher value enforces a prolonged period of cautious, tighter outlier detection.
\end{itemize}
